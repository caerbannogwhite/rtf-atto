# rtf-atto

rtf-atto is an RTF reader in C++17.
It targets clinical tables made by SAS and also reads general RTF.
A writer, a WebAssembly build and a TypeScript renderer will come later.

## Build and test

With the default generator (Visual Studio on Windows, Make on Linux and macOS):

    cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
    cmake --build build --config Release -j 8
    ctest --test-dir build -C Release --output-on-failure

With Ninja:

    cmake -S . -B build-gcc -G Ninja -DCMAKE_BUILD_TYPE=Release
    cmake --build build-gcc
    ctest --test-dir build-gcc --output-on-failure

CMake options:

- `RTF_BUILD_TESTS` builds the tests. It is on when rtf-atto is the top-level project.
- `RTF_BUILD_TOOLS` builds the `rtf2json` command. It is on by default.
- `RTF_SANITIZE` builds with AddressSanitizer and UBSan. It does not apply to MSVC.
- `RTF_FUZZ` builds the libFuzzer target `fuzz_parse`. It needs Clang.

The tests need Python 3 for the text comparison against `test/tools/rtf_text.py`.
The environment variable `RTF_MUTATIONS` sets the number of mutations in the
mutation test. `RTF_LARGE_SECONDS` sets the time budget of the large-input test.

## The command

    rtf2json [--json|--text|--tables|--summary] [--version] <file>

- `--json` writes the document model as JSON. This is the default.
- `--text` writes the plain text of the document.
- `--tables` writes the logical tables as JSON.
- `--summary` writes the file name, the number of sections and tables,
  the column names of each table and the warning codes.
- `--version` prints the version.

Exit codes: 0 for success, 1 when the file is not RTF, 2 for a usage error
or a file that cannot be read.

## Fixtures and goldens

The files in `test/fixtures` are the test inputs. There are 19.
Ten are generated by `test/tools/make_fixtures.py`. Five are written by
hand. Four come from the owner's own synthetic
files: three saved by Word (`msword_*.rtf`) and one made by SAS
(`sas_disposition.rtf`). Each fixture has a golden `.json` file and a
`.tables.json` file.

To regenerate the goldens after a deliberate change:

    python test/tools/regen_goldens.py build/Release/rtf2json.exe test/fixtures

Review the diff of the goldens like code. A changed golden means the
output of the reader changed.

## Local samples

The owner keeps private SAS files outside the repository.
This script checks them:

    RTF_SAMPLES_DIR=<dir> [RTF2JSON=<path>] [PYTHON=<command>] bash test/local/samples.sh

- `RTF_SAMPLES_DIR` is the directory with the `.rtf` files. It is required.
- `RTF2JSON` is the tool. By default the script looks in `build` and `build-gcc`.
- `PYTHON` is the Python command. By default it is `python3`, else `python`.

On the first run the script writes `expected.txt` into the samples directory.
Review it against what Word shows. On later runs it compares each file with
its block and reports `new` for files without one. It also compares the text
of every file with `rtf_text.py`. `expected.txt` stays next to the samples
and is never committed.

## Status

and the DuckDB integration belong to later plans. See `docs/plans/`.
